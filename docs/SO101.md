# SO-101 with NormaCore pgripper

The `so101-station` command loads the supplied six-motor calibration and reads
the arm through the NormaCore Station TCP API. It runs independently of the
ElRobot daemon, CLI, IK, poses, and calibration archive. ROS is not required.

## Imported calibration

Source: [AtharvaBhorpe/so_arm101_pgripper](https://github.com/AtharvaBhorpe/so_arm101_pgripper/tree/c79830e72ec5de71ad586f6119a3be0405d51b4c),
revision `c79830e72ec5de71ad586f6119a3be0405d51b4c`.

The description package's `config` directory has canonical joint limits and ROS
controller/display settings. The measured motor calibration is under the
upstream `config/hardware/so_arm101_pgripper_follower.*` files.

Copies are bundled under `src/so101_station/profiles/pgripper/`:

| Local file | Used for |
| --- | --- |
| `calibration.json` | Motor IDs, measured tick ranges, expected EEPROM offsets |
| `state.yaml` | Center ticks and directions for tick/radian conversion |
| `control.yaml` | Cross-check against the calibration and state exports; never applied to hardware |
| `joint_limits.yaml` | Measured angular limits |
| `canonical_joint_limits.yaml` | Mechanical limits from the robot description |
| `SOURCE.json` | Exact upstream paths and revision |

The copied files are unchanged apart from their local names. Upstream notices
and license texts are included. ROS controller and RViz settings are not loaded
by Station and are not required by this adapter.

This profile is for the **NormaCore parallel pgripper variant**, not the stock
SO-101 gripper. These are measurements of the source arm. Importing them does
not establish that another physical arm has the same calibration.

## Coordinate conventions

| ID | Joint | Mapping |
| --- | --- | --- |
| 1–4 | shoulder_pan, shoulder_lift, elbow_flex, wrist_flex | Tick 2048 = zero radians, increasing ticks = increasing angle |
| 5 | wrist_roll | Tick 2048 = upright; measured limits 260–2686 are asymmetric |
| 6 | gripper | Tick 3484 = open/zero radians; tick 2048 = closed/positive angle |

The arm formula is `angle = direction * (tick - center_tick) * 2π / 4096`.
Servo position registers already reflect the EEPROM homing offset. It must
not be subtracted a second time. Homing offsets use STS sign-magnitude encoding
(sign bit 11), not a signed 16-bit integer.

The adapter intersects calibrated angular limits, canonical limits, and measured
tick endpoints. The extra eight-tick tolerance in the ROS gripper limits is not
permitted as physical command travel. Invalid targets raise an error rather
than silently clamping. Gripper opening uses `0 = closed`, `1 = open`.

## Commands

From this worktree, inspect the profile or preview a target without connecting:

```bash
uv run --frozen so101-station profile
uv run --frozen so101-station preview wrist_roll --from-tick 2048 --delta-deg 2
uv run --frozen so101-station gripper-preview --open 1
```

`preview` permits at most three degrees and checks the starting and target
positions. `--from-tick` is explicitly supplied for offline calculation: the
preview does not establish that it is the arm's current position. Neither
preview command sends a motor command. `gripper-preview` only converts a
fraction; it does not plan speed or gripping force.

If the project environment has not been installed, these same commands work as
`PYTHONPATH=src python3 -m so101_station ...` with Python 3.12 and PyYAML.

Once Station is running on the robot host, discover buses and compare the
selected bus to the profile:

```bash
uv run --frozen so101-station discover --host 127.0.0.1:8888
uv run --frozen so101-station status --host 127.0.0.1:8888 --bus-serial YOUR_SO101_BUS
```

`status` requires an exact bus serial and exactly motor IDs 1–6. It checks raw
register availability, EEPROM offsets/limits, position mode, servo errors,
current tick bounds, and source timestamps. The newest stored sample must be
at most 500 ms old and no more than 100 ms in the future. Remote host clocks
must therefore be synchronized. Station's own calibration ranges are reported
separately; they are not silently substituted for this profile.

Exit codes: `0` for a successful inspection/preview, `1` for live state that
does not match, and `2` for invalid input, connection/stream failure, or timeout.
`profile_matches_live_state` means that those numeric checks passed. It does
not verify physical joint directions, camera geometry, or collision clearance.

The `so101-station` CLI is read-only: it does not start Station, enable/disable torque,
write offsets/PIDs, freeze calibration, or execute motion. An EEPROM mismatch
is reported for diagnosis; it is never repaired automatically. Do not apply
the ElRobot `calibration/station-calib.zip` to this SO-101.

## Validation

For the first supported-arm test, `python -m so101_station.bench --bus-serial BUS` previews a one-degree wrist target. Add `--expected-tick TICK --execute` only after inspecting the live position and clearing the wrist. It commands motor 5 only, uses RAM speed/torque limits, checks encoder travel, returns to the starting tick, and retains wrist torque. The other five motors must remain unpowered and the arm supported. This does not require a table map and does not establish full-arm collision clearance.

On 2026-11-21, bus 5B91029197 completed the real wrist test: 2647 → 2636 → 2647 ticks. See logs/so101-first-control/wrist-test-executed.json and the cleanup handoff for the resulting motor state.

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -p 'test_so101_*.py' -v
```

Tests use the real generated protobuf codec with synthetic registers. They cover
all measured tick round trips, asymmetric wrist limits, gripper direction and
padding, conflicting files, sign-magnitude offsets, wrong/missing motors,
stale samples, bounded reads, connection cleanup, and rejection of writes.
They do not contact hardware.
